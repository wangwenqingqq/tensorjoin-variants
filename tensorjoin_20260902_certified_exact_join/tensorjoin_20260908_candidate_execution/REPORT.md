# TensorJoin 在线候选生成与剩余矩阵执行实验

完成日期：2026-09-08。实验方案在 GPU 计时前固定；本轮不主张新颖性。

**结论：按活跃行／列压紧的执行方式在低密度点获得稳定净收益，但六阈值混合负载未通过预设的 5% 门槛。**
九次保留调用的逐点中位数等权合并后，最强固定对照为 project64，耗时 109.67 ms；packed16 为 105.99 ms，时间节省 3.35%。
三个独立进程各自的节省为 3.47%、1.22%、4.19%，全部低于 5%。因此不进入本原型的继续调参阶段。

## 测了什么

沿用完整 CIFAR 60,000×512 FP32 向量、六个冻结阈值以及 FP64 终端合同。返回完整、排序后的有向 CPU pair 数组，含自身连接。所有方法共享现有 FP16 初筛、冻结 FP32 精化、冻结 FP64 终端和 CUB 输出；新矩形核保留原 FP16 误差区间公式，只改变 tile 形状和索引。

| 代号 | 方法 |
|---|---|
| original_full | 原顺序强 FP16 全量 64×64 扫描 |
| layout_full | PCA 排序后全量扫描，计入原 ID 恢复 |
| bbox64 | 输入建立投影包围盒，查询时按安全界删掉 64×64 块 |
| project64 | 查询时计算全部 pair 的 64 维保守投影距离，剩余任务按 64×64 回退 |
| subtile16 | 同一投影判据，执行含候选的 16×16 子块 |
| packed16 | 若一个 64×64 块的候选只占 ≤16 行或列，压紧为 16×64 或 64×16；其他块完整回退 |

PCA 投影及排序仅使用输入。运行时不读取 oracle 占用信息。筛选核直接生成标志及压紧索引；GPU nonzero 生成任务表。压紧两侧都可行时选较少的活跃维度，平局选行。各形状每批最多 2^24 个矩阵单元。投影维数、形状和规则均未按计时调整。

| k16 | 54.56 | 54.51 | 49.14 | 42.49 | 43.34 | 34.13 |
| k64 | 58.89 | 59.55 | 55.36 | 50.74 | 60.13 | 49.48 |
| original | 65.37 | 72.55 | 65.16 | 64.09 | 74.55 | 58.59 |

| 阈值 | 压紧相对投影＋整块的加速（九次中位数之比） | 三进程各自中位数之比的范围 |

## 归因：少算并不自动更快

原阈值下，投影保留 39,514,416 个上三角候选，占 1,800,030,000 个有效 pair 的 **2.20%**。上轮 FP64 投影普查的候选比例约 1.78%；本轮 FP16 安全余量更大，所以不应照搬旧剪枝率。

| 方法 | 执行的矩阵单元数 | 相对完整矩阵容量 | 距离初筛 CUDA 事件区间 | 过滤与任务表事件区间 | 批数 |
|---|---:|---:|---:|---:|---:|
| original_full | 1,803,841,536 | 100.00% | 18.30 ms | — | 108 |
| project64 | 1,303,781,376 | 72.28% | 13.04 ms | 3.49 ms | 78 |
| subtile16 | 1,083,907,840 | 60.09% | 23.00 ms | 4.21 ms | 65 |
| packed16 | 1,025,808,384 | 56.87% | 10.69 ms | 4.53 ms | 62 |

容量计数包含方形 tile 的填充和对角线以下单元，是硬件执行量代理，不是有效 pair 数。诊断只做单次，使用 CUDA 事件夹住阶段，区间可能包含主机发射造成的等待；不作为最终速度统计。

subtile16 的矩阵容量低于 project64，但初筛区间约从 13.04 ms 增至 23.00 ms。小块执行成本抵消了少算的收益。packed16 保留另一侧 64 点，初筛约 10.69 ms，同时把批数从 78 减至 62；其过滤与列表成本约从 3.49 ms 增至 4.52 ms。实际收益来自这个整体交换，不能仅归因于 pair 减少，也不能把减少的批间同步排除在机制之外。

最高输出密度的一次原顺序诊断中，输出收尾约 287.57 ms／总计 356.74 ms（约 80.6%）。这解释了为何低密度明显获益，但六阈值按时间等权合并的整体改善很小。

相对原顺序 FP16，合并查询加速约 1.101×；其中包含常规投影过滤的收益。相对更强的 project64，压紧机制的新增节省只有 3.35%，不得将全部收益当成压紧独有贡献。

## 构建成本及冷启动

初次公共 CPU 预处理实测 0.865 s，其中 PCA／排序 0.467 s，投影半精度元数据／重排 0.112 s，包围盒 0.286 s。

| 原阈值，从现成 CPU 向量开始 | 公共构建 | 查询 | 总计 |
|---|---:|---:|---:|
| layout_full | 712.69 ms | 59.28 ms | 771.97 ms |
| bbox64 | 665.99 ms | 55.49 ms | 721.48 ms |
| project64 | 669.20 ms | 51.62 ms | 720.82 ms |
| subtile16 | 670.68 ms | 59.88 ms | 730.56 ms |
| packed16 | 667.86 ms | 47.74 ms | 715.60 ms |

本原型冷启动路径统一构建整套公共索引，包括有些执行模式不使用的包围盒；它是实际测得的公共构建路径，**不是每个方法分别最小化后的构建下限**。即使只算 PCA／排序，成本也已显著高于一次原顺序查询。因此现有收益限于索引可复用的场景，不能声称单次从头执行更快。冷启动为一次诊断，不计算置信区间。

## 正确性与数值范围

共 **517 次完整调用**通过：准入 77 次（含 5 次冷启动）、独立 KD 诊断 8 次、确认预热 108 次、保留测量 324 次。前两组共 85 次逐元素比对完整 FP64 参考，其余 432 次验证结果个数与 SHA256。全部方法的直接接受、第一阶段不确定、最终 FP64 和总输出计数一致。

独立 CPU 直接差分检查覆盖每阈值 201 个 tile、801,424 个有效 pair，共 1,206 个 tile-阈值检查、4,808,544 个 pair-阈值检查。检查候选覆盖、压紧索引的合法性／唯一性、对角线、自身和 32 点尾块。另换 KD 几何顺序，在原阈值下完整运行四种执行方式并核对相同参考；其单次诊断不计入正式统计，也不算独立数据集。

GPU 投影使用显式清零次正规数的 FP16 坐标。全局 H≈2.2010，E≈0.0007082；按协议加上 8HE+4E²、继承的累积误差、投影正交误差和终端保护，平方距离安全余量为约 **0.0136634**，阈值向上转换为 FP32。该保护刻意保守。完整数据核验是本输入的实证证据，不替代任意输入、任意编译器的普适证明。

## 对 TensorJoin 的作用及停止决定

1. 这次已经测到在线候选生成、压紧、剩余矩阵执行、精化和完整输出的实际净成本，补上了上一轮只有结构统计的缺口。
2. 活跃行／列集中的结构在低密度查询上可被利用；简单 16×16 切块多数点更慢，说明执行粒度确实影响结果。这可以支撑有内容的消融或下一步狭窄机制假设。
3. 预设整体门槛未通过，因此不能将本原型包装成已经成立的论文核心。按协议停止对这套原型的继续调参；若继续，应先把假设限定为可复用索引的低输出查询，在未参与选题的新数据上与普通投影＋矩形／稀疏执行组合比较。
4. 本轮没有运行 FaSTED、TED-Join、RT-HiSS、TC-GNN 或 FlashSparse。它们的先例不能靠本地 FP16 基线比较排除；投影下界、块回退、稀疏压紧本身均不能在此被认定为新贡献。也没有挽救此前 INT8／FP16 精度 planner 的证据。
